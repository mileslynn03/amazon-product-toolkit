## 真实访问与抓取结果

使用前端提供的示例 ASIN `B07XJ8C8F5`、美国站进行测试。真实浏览器测试采用无头 Chromium；完整爬虫测试仅将浏览器启动参数改为无头，其余抓取逻辑沿用现有实现。这与用户手动操作的有头浏览器环境有差异。

1. 不带已保存登录态直接访问详情页：HTTP 200，但出现验证表单和“Continue shopping”提示，评论节点为 0。HTTP 200 不能作为页面抓取成功的依据。
2. 不带登录态直接访问评论页：本次返回 HTTP 404。该结果不证明 ASIN 一定无效，也不足以判断整个站点的可用性。
3. 调用快速扫描完整流程：约 40.3 秒后返回 0 条，进度提示“详情页内嵌评论，+0 条”，未报告明确失败。
4. 调用深度抓取完整流程：加载现有美国站登录态后，被重定向到登录页；约 33.2 秒后返回 0 条，未向任务层抛出失败。

没有完成有效登录后的真实多页抓取，因此本次不能承诺修复代码后一定能从亚马逊取得评论。后续验收需要使用确认存在、确有评论的商品链接和有效会话。

## 已确认的问题与优先级

### P0：失败、拦截、登录失效与成功没有明确区分

- `scraper/crawler.py` 的快速扫描未调用验证码处理逻辑；被拦截后继续等评论，最后返回空列表。
- 爬虫会将部分异常、登录跳转等情况转换为空列表；任务层无法可靠区分“商品无评论”与“抓取失败”。
- 模拟爬虫抛出异常时，任务事件仍按 `result(count=0)`、`error`、`complete` 发出；前端收到 `complete` 后显示“抓取完成”。
- `task_manager.py:94` 发出的完成事件不含 done/total；`static/index.html:237` 将缺失值按 0 处理。本地执行前端事件逻辑后，原本 1/1 的进度变为 0%、0/0。

建议先定义成功、无评论、失败、需登录、需验证、取消等状态，让前端、导出和日志保留具体原因。

### P0：登录有效性判断和浏览器线程管理不可靠

- `scraper/browser.py:41` 仅通过登录态文件存在判断已登录。
- 本地美国站状态文件存在，19 个 cookie 中有 6 个持久 cookie 已过期；单凭这些数量不能判断会话有效性，但完整深度抓取已实际发生登录跳转。
- 登录和抓取分别启动线程，却复用模块级同步 Playwright 对象。锁仅覆盖部分创建/读写操作，没有覆盖完整登录或抓取过程，接口也未阻止两者同时运行。
- 两线程本地浏览器实验已复现 `Cannot switch to a different thread`。这证明重叠操作有明确线程错误风险，但不代表每次顺序操作都会触发。

建议统一浏览器所属线程，禁止登录与抓取重叠；界面区分“已保存会话”和“已验证登录”，实际遇到登录跳转时更新状态。

### P1：传统分页只抓第一页

- `scraper/crawler.py:88` 只等待评论节点数增加，适用于追加节点的“加载更多”。
- 传统分页会替换节点，节点数可以保持不变。当前代码因此提示“无新增评论”并提前结束。
- 本地浏览器双页样例中，页面已经显示第二页，返回结果仍只有第一页。
- 下一轮使用 `start=parsed_count` 解析，也需要区分“追加”与“替换”两种情况。

建议分别判断两类翻页完成条件，并通过评论 ID 或稳定指纹去重；分别验证追加、替换、尾页与重复页。

### P1：刷新、断线和重复登录会让操作流程失效

- `TaskManager.snapshot()` 已定义，但没有暴露状态接口，SSE 订阅时也没有发送快照；前端初始化仅获取配置。
- 刷新或 SSE 重连会丢失已有结果和任务状态，服务仍可能继续运行。
- 保存登录态时按钮会被禁用并改成“保存中…”，后续 `login_ready` 不恢复按钮。本地前端复现第二次登录时保存按钮仍禁用。
- 登录等待没有超时或取消流程，反复启动登录还会替换共享事件。

### P2：多站点数据正确性和输入校验不足

- 评分解析只取第一个数字：`4,5 von 5 Sternen` 被解析为 4.0；`5つ星のうち4.0` 被解析为 5.0。本地函数调用已复现，尚未逐站验证真实 DOM。
- `/api/start` 使用无约束字典。本地隔离爬虫后提交 `asins="bad"`、无效国家、无效模式和负数上限，接口返回成功并创建 b/a/d 三个任务。
- README 中仍有 Streamlit rerun 等旧说明，与当前 FastAPI 实现不一致。

## 建议的推进顺序与验收门槛

1. 先修正任务状态、失败原因、登录有效性和浏览器线程归属。验收：拦截、过期登录、网络错误都能准确展示，失败不会表现为成功。
2. 只选美国站一个确认有效的商品，先验证真实单页评论：条数、标题、正文、评分与浏览器内容一致，再导出核对。
3. 完成真实多页抓取与本地两种分页回归，核对抓取上限、去重和停止行为。
4. 验证刷新恢复、断线恢复、再次登录、连续两次任务和批量任务。
5. 逐站验证页面结构和本地化解析，再将站点标记为已验证支持。

项目下一里程碑应是“一个站点、一个真实商品，从有效会话抓到真实评论并正确导出”，再推进批量与多站点验收。
